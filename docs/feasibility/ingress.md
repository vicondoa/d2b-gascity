# U14 ingress feasibility

This proof checks the planned private ingress shape for the embedded Gas City
supervisor dashboard. It is a credential-free fixture, not a production
deployment module or a standalone dashboard.

## Result

The exact U2 runtime can be placed behind a TinyAuth and Nginx relay without
exposing the supervisor beyond loopback. The relay performs authentication
before forwarding requests and preserves the external Host and control
headers. The relay rejects wrong-Origin and cross-site browser mutations;
Gas City rejects missing `X-GC-Request` and invalid Host values.

The fixture uses an ephemeral supervisor port rather than the production
default `127.0.0.1:8372`. This avoids port ownership and makes repeated local
runs independent. The production implication is recorded below.

## Exact runtime and commands

The proof uses:

- Gas City build ID `f6741d94861aa14f0253deffbe9efb1cb3a35d92`
- TinyAuth `5.1.3`
- Nginx `1.30.2`

From this repository:

```sh
nix build .#packages.x86_64-linux.gas-city-contributor
D2B_INGRESS_RUNTIME=./result python3 tests/fixtures/ingress/run.py
```

The fixture generates its fake password hash, users file, ports, configs, and
runtime state below `.scratch/ingress-runs/`. It does not read or write a
committed credential, cookie, database, log, socket, or host configuration.
Each run removes its private directory after checking that its owned process
groups are gone.

Additional local checks:

```sh
for run in 1 2; do
  D2B_INGRESS_RUNTIME=./result python3 tests/fixtures/ingress/run.py
done
python3 -m py_compile tests/fixtures/ingress/run.py
git diff --check
```

The build, one exact-runtime run, two repeat runs, Python compilation, and
diff check all returned success. The fixture's final cleanup check reported:

```text
PASS no ingress run directory remains
```

Python compilation creates `__pycache__`; it is removed after validation and
is not part of the fixture.

## Verified topology

```text
HTTP client
  Host: gascity.example.test
  Origin: http://gascity.example.test
             |
             v
Nginx relay, 127.0.0.1:<ephemeral relay port>
  auth_request -> TinyAuth, 127.0.0.1:<ephemeral TinyAuth port>
  authenticated proxy -> supervisor, 127.0.0.1:<ephemeral supervisor port>
                                      |
                                      v
                         embedded dashboard, API, and SSE
```

The fixture also starts one loopback-only Python helper SSE endpoint. It is
test infrastructure only and is used to measure first-byte buffering and
`Last-Event-ID` forwarding without inventing a Gas City endpoint.

The supervisor configuration generated by the fixture is equivalent to:

```toml
[supervisor]
bind = "127.0.0.1"
port = <ephemeral>
allowed_hosts = ["gascity.example.test"]
```

`allowed_origins`, `allow_mutations`, `write_auth_*`, and `read_auth_*` are
intentionally absent. The relay is the authentication boundary. It forwards
the external `Host`, `Origin`, `Sec-Fetch-Site`, native nonempty
`X-GC-Request`, and `Last-Event-ID`. It overwrites forwarded identity headers
with values derived from the current request and does not trust a caller's
`X-Forwarded-*` values.

The mutation proof uses `X-GC-Request: dashboard`, the native value from
`internal/api/dashboardspa/web/frontend/src/supervisor/client.ts` at the U2
Gas City source revision. The fixture does not synthesize a different CSRF
value.

## Bootstrap and lifecycle proof

The fixture creates a private state root and runs the supported upstream
sequence:

```text
gc init --template empty --no-start --skip-provider-readiness --yes <city>
gc supervisor run
gc start <city> --json
```

The first command creates a minimal stopped city. The foreground supervisor
is the only Gas City server process. `gc start` performs the supported
registration/start path, and the fixture waits for the city to become ready.
There is no second dashboard process and no user systemd unit.

The fixture keeps the real `HOME` because this upstream `gc start` path rejects
an overridden HOME. All mutable Gas City, XDG, Git, and Dolt paths are
redirected into the private run directory, and the fixture creates a fake
Dolt identity before initialization.

## Proof results

`run.py` passed each of these checks:

1. An unauthenticated request to `/agents?tab=events&fixture=1` returns a
   TinyAuth login redirect and preserves the exact path and query in the
   return URI.
2. Fake login returns a session cookie containing `Secure`, `HttpOnly`, and
   `SameSite=Lax`.
3. The authenticated embedded dashboard HTML, one discovered asset,
   `/health`, and `/v0/city/city/status` all reach the supervisor through the
   relay.
4. The actual supervisor `/v0/events/stream` endpoint opens through the
   relay with event-stream and no-cache response headers.
5. The helper SSE endpoint sends its first event before the delayed second
   event, proving the relay's buffering setting, and receives the exact
   `Last-Event-ID` value on reconnect.
6. Gas City receives the valid and missing-CSRF `PATCH /v0/city/city`
   requests through the relay. Gas City rejects a missing `X-GC-Request`.
   The relay rejects a wrong Origin and `Sec-Fetch-Site: cross-site`. With
   the external Origin, `Sec-Fetch-Site: same-origin`, and a nonempty native
   request header, Gas City suspends the fixture city and then restores it.
7. A wrong external Host is rejected by both relay and supervisor. Forged
   `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-Port`, and
   `X-Forwarded-For` values do not change Gas City decisions.
8. After the supervisor process group is terminated, an authenticated relay
   read reports temporary upstream unavailability. Starting `gc supervisor
   run` again restores authenticated reads without starting another dashboard
   process.
9. The generated supervisor configuration contains the one external
   `allowed_hosts` value and none of the forbidden CORS or read/write
   authorization overrides.
10. The runtime reports the exact Gas City, TinyAuth, and Nginx pins listed
    above.

The fixture owns each spawned process as a new process group. Cleanup signals
only groups discovered from the fixture's root PIDs and private run path,
waits, escalates to `SIGKILL` if necessary, and reports any remaining
descendant. The repeated runs produced no process-leak failure and left no
`ingress-runs/run-*` directory.

## Configuration implications

The eventual service configuration should:

- bind the supervisor only to `127.0.0.1:8372`;
- put the deployment's external dashboard Host in `allowed_hosts`;
- keep the supervisor's CORS and read/write authorization override options
  absent when TinyAuth and the relay are the authority;
- preserve the external Host and Origin through the relay;
- preserve `Sec-Fetch-Site`, native `X-GC-Request`, and `Last-Event-ID`;
- overwrite, rather than accept, forwarded client identity headers;
- keep the supervisor unreachable from the external network except through
  the authenticated relay.

The fixture's external authority is only the placeholder
`http://gascity.example.test`. No private authority, certificate, deployment
address, or credential is embedded in the source.

## Deliberate proof boundaries

This is the early U14 feasibility fixture. The following are intentionally
left to the later browser and deployment work:

- The Python HTTP client manually resends the Secure cookie. A plain HTTP
  client does not implement a browser's Secure-cookie policy, so this is not a
  browser conformance claim.
- One real supervisor SSE connection is opened. A fixture-only SSE endpoint
  supplies a delayed second event to prove unbuffered delivery and exact
  `Last-Event-ID` forwarding. Generating and reconnecting a real supervisor
  event is outside this lightweight proof.
- The fixture does not claim logout, expiry, key rotation, rate limiting,
  keyboard navigation, or screen-reader conformance. Those require the
  browser journey and accessibility checks planned for U8.
- All fixture requests originate on loopback. An unprivileged test cannot
  create a non-loopback source without changing host networking. Nginx still
  has `allow 127.0.0.1; deny all;`, and the limitation is recorded rather
  than represented as a false wrong-source result.

No mTLS is used. The accepted residual risk is private HTTP between the
same-host relay and loopback supervisor, plus the need for a real deployment
firewall/source policy if the relay listener is made reachable from a private
network. The external-facing deployment must add its own TLS termination and
source restrictions; this fixture does not make plain HTTP suitable for a
public listener.

## Stop conditions

The U14 stop conditions were not encountered: TinyAuth authentication occurs
inside the relay before upstream forwarding, the deep-link URI and required
same-origin headers survive the relay, the supervisor remains loopback-only,
and no sensitive auth material appears in fixture source, argv, or output.

Any future implementation that requires a public supervisor bind, a separate
dashboard server, relay-side credential bypass, loss of the native control
headers, or secrets in argv/logs must stop before U4/U8 and receive a new
design decision.
